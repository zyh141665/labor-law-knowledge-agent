# 劳动法知识库 Agent 面试问答准备

本稿依据当前代码整理，优先级表示复习建议，不表示某家公司一定会问。不要机械背诵，
也不要把 AI 协助完成的代码说成全部独立完成。回答时区分实现、测试、历史记录与待完成事项。

## 0 项目介绍

我在原有企业知识库练习上扩展了一个劳动法领域的问答 Agent。后端用 DeepSeek、
LangGraph 和本地向量加 BM25 混合检索，从两部法律共 205 条文本中查找证据，
输出结构化回答，再校验来源与逐字引用。

Streamlit 通过 HTTP 访问 FastAPI，界面显示处理阶段与通过校验的最终答案。
项目还实现了会话检查点、独立聊天历史、跨会话记忆、令牌身份校验及自动化测试。

目前仍是学习与作品集项目，不是完整法律咨询服务。引用真实不代表结论完整正确，
也没有承诺面向公众的多用户登录、高并发或云部署能力。

## 1 项目定位

### Q1 简单介绍项目

按第 0 节介绍，然后展开一次真实请求：认证、恢复状态、读取记忆、检索、生成、校验、记录。
重点说清每步解决的问题，不只罗列技术名称。

### Q2 为什么选择劳动法

条文有清晰的编号和段落边界，适合练习切分、检索与引用校验；
相似表述也方便暴露检索问题。但两部法律不代表全部适用法律，知识库范围必须明确。

### Q3 项目中难点是什么

可以讲自己复现过的失败：多法源 source_id 冲突、正确证据未进入 Top-K、
引用真实但结论缺乏支持。用“现象、检查方法、改动、验证结果”回答；
没有日志和复现依据的经历不要直接背成亲身事实。

## 2 架构与选型

### Q4 为什么用 LangGraph

它提供显式状态、节点和条件边、检查点、节点更新事件，便于表达
“模型 → 工具 → 模型 → 校验”循环。普通 Python 循环也能实现；
不能说不用框架就做不了 Agent，更不需要笼统贬低其他框架。

### Q5 为什么前后端分离

Streamlit 只通过 AgentApiClient 请求后端，不加载 Embedding 或打开业务数据库。
好处是职责清楚、业务资源集中管理、其他客户端可复用 HTTP 接口。
Streamlit 本来就能作为服务器给浏览器用，不分离也不意味着必须把源码和密钥给用户。

### Q6 三层状态分别存在哪里

| 数据 | 存储 | 作用范围 | 删除会话时 |
| --- | --- | --- | --- |
| Agent 检查点 | checkpoints_v2.sqlite | user_id 与 thread_id 组合 | 调用官方 delete_thread 清除 |
| 用户长期记忆 | memory.sqlite | 用户命名空间 | 保留，不属于该会话 |
| 界面聊天历史 | chat_history.sqlite | user_id 与 thread_id | 清除对应消息 |

检查点包含模型输入和工具过程；聊天历史是给界面的问答投影。
长期记忆目前没有公开删除接口，不要说已经有完整记忆管理后台。

### Q7 为什么不是逐 Token 流

模型输出完整 JSON 后，才能执行现有的结构和引用校验。
为坚持先校验再展示，当前只流式发送处理阶段，最后一次性展示验证后的答案。
SSE 本身并不限制只能发阶段事件，这是本项目的实现选择。

### Q8 为什么选 SSE 而不是 WebSocket

当前只需要服务器连续发送进度和结果，HTTP 事件流足够。
客户端实际使用 httpx 发送 POST 并解析 SSE，不是浏览器原生 EventSource；
没有实现自动重连和断点恢复，不能声称浏览器会自动重连这条请求。

## 3 检索

### Q9 完整讲一次请求

1. 客户端携带 Bearer 令牌提交 user_id、thread_id、question。
2. 后端验证令牌与 user_id 一致，再进入服务层。
3. 读取用户长期记忆，恢复该用户该会话的检查点。
4. 第一轮 tool_choice=required，要求模型调用知识库工具。
5. 校验工具参数，执行向量与 BM25 混合检索和门控。
6. 工具结果交回模型，可以继续补查或生成结构化答案。
7. 校验来源和逐字引文，通过后记录聊天历史并返回。

默认 Top-K 是 4，但工具参数允许模型选择 1 至 5，并不是每次固定返回四条。
单个用户问题 max_rounds=5；图的 recursion_limit=20 统计图执行步骤，两者不是同一指标。

### Q10 为什么混合检索以及怎么融合

向量提供语义信号，BM25 提供字面信号。两者各有盲区，组合是为了改善召回。
BM25 原始分 b 通过 b/(b+5) 压缩，再与余弦分等权相加。
这不是学习式重排，也不是把两路分数转换成了可信概率；收益需用当前数据验证。

### Q11 为什么使用中文字符 bigram

中文连续文本按相邻两字切分，数字英文按连续片段保留，并处理部分疑问停用词。
它不依赖词典，适合当前小语料实验；不等于完整理解中文词义，也不能保证比 jieba 更好。
没有正式对比实验时，只介绍实现取舍，不编造性能结论。

### Q12 为什么使用两个门控信号

向量分达到 0.6，或者 idf 加权关键词覆盖率达到 0.15，即进入候选。
门控先过滤候选，再按融合分排序。通过只代表可能相关，不代表一定有答案。

当前 BM25 使用 b/(b+5)，不是按该查询最大值归一化。
“最大值永远为 1”的问题只适用于另一种按最大值归一化的策略，不能混为一谈。

### Q13 阈值怎么确定

目前是小规模实验中的经验配置，需要固定模型、索引、标注集后扫描参数，
比较域内命中和误拒答、域外放行，以及端到端结果。
已有诊断题与调参有重合，没有足够证据宣称严格划分了独立 holdout。
未保存可复核记录的提升百分比，不应在面试中当作现测结果。

### Q14 如何切分文档

当前要求文本文件每行以第 X 条开头，一条法条作为一个 chunk。
source_id 使用“法律简称#条号”，避免多法源撞号。
很长的条文可以考虑按款项进一步切分，同时保留法律、条号等元数据。
固定长度切分不一定令逐字校验失效，但可能破坏语义和上下文完整性。

### Q15 为什么没有接向量数据库

目前仅 205 个 512 维向量，用 NumPy 全量计算便于理解和调试，
不必单独部署检索服务。FAISS 是向量检索库，不应与独立数据库服务完全混称。
是否更换取决于规模、并发、延迟、更新和过滤需求，不能给一个放之四海皆准的条数门槛。

### Q16 为什么没做 Rerank

当前只有融合排序，还没有 cross-encoder 重排或查询改写。
当正确资料在较后候选中时，可比较更大召回集加重排的效果与成本。
不能说向量模型完全没有主客体能力；当前只是对一些相似表述区分不足。
也不能说现有引用校验必然兜住排序错误，真实引用同样可能被错误解读。

## 4 引用与拒答

### Q17 如何降低模型编造

检索门控、提示词、结构化输出、本地引用校验共同约束。
source_id 必须来自本轮检索，quote 必须是对应原文的逐字子串。
这些规则能拦截伪造引文，但不能证明正文所有推理都得到证据支持。

### Q18 为什么逐字比对而不是只比相似度

这个字段定义为原文引用，不是摘要；语义相似的改写不满足字段契约。
因此使用可复现的子串判断。正文可以组织语言，引文字段必须复制原文。
还需要另外评估“结论是否得到证据支持”，不能拿真实引用代替这一步。

### Q19 为什么要求 JSON

固定 answer、refused、citations 等字段，方便解析、Pydantic 校验和前端展示。
JSON Schema 约束结构，不保证事实正确；还要处理供应商能力差异和验证失败。
换兼容接口时必须验证 Responses、工具调用及结构化输出支持，不能只改 URL 就保证可用。

### Q20 如何处理不知道

证据不足时 refused=true，明确说明无法确定。
可以不附引用，也可以附本次查过但不足以回答的真实条文并说明限制。
提示词、本地校验和生成评估已经统一这一规则。
允许带引用不代表允许伪造引用，引用真实性仍由正式工作流检查。

## 5 评估

### Q21 如何知道效果

分别看检索和生成。固定检索集 7 条、固定生成集 8 条；
另有 18 条域内和 13 条域外的检索诊断题。
Top-1、Top-K 至少一条可接受来源命中、域内误拒答、域外门控拒绝应分开报告。
生成集检查拒答、来源集合和关键字符串，不能代替全面语义正确性评估。

2026 年 10 月 31 日留存的报告分别记录 7/7 和 8/8。
它们是历史文件结果，不是修复后重新调用真实模型取得的结果。
78%、94%、69% 等旧笔记数字在保存新的可复核运行结果前，不作为当前指标引用。

### Q22 评估集是否会过拟合

会，尤其题量很少、反复根据同一批失败调参时。
需要标注依据、样本版本、开发集与独立测试集，以及按问题类型分层。
当前不能声称所有诊断题从未用于调参。手工测试集存在也不自动证明无泄漏。

### Q23 举一个失败案例

可以先复现“用人单位解除”和“劳动者解除”这类角色相反问题，
观察正确来源是否进入候选，再判断是召回、排序还是生成问题。
没有本次输出时不要死背“正确资料一定排第七、第八”；排名会随模型、索引和配置变化。

### Q24 增加法律后指标为什么可能涨跌

候选竞争、法源覆盖、相似文本、门控和评估标签都可能变化。
增加语料不必然降低拒答质量，也不能简单归因于题量。
应在同一份冻结样本上比较，并把新增样本单独统计，避免混淆分母变化与能力变化。

## 6 工程

### Q25 如何讲排错

先选自己能复现的案例，例如未携带令牌得到 401、启动脚本漏带令牌误报后端不可用、
只删聊天历史而保留检查点、直接写记忆绕过前端审核。
分别说明现象、原因、改动、回归测试。旧笔记中的抓包、OOM 等经历需自行核实后再使用。

### Q26 瓶颈在哪里

检索、本地校验和模型请求都应分别计时。当前代码有整轮与 HTTP 耗时日志，
但没有足够基准证明“一定毫秒级检索”或“瓶颈完全不在程序”。
典型一轮可能两次模型调用，但也可能多轮；用日志而不是猜测回答。

### Q27 为什么自己写 BM25

当前实现同时需要 BM25 打分和 idf 加权关键词覆盖率，代码小、易测试。
使用现成库加一层覆盖率计算也可行，不是只有自己写才能实现。
生产扩容时应评估倒排索引与成熟检索引擎，而不是无限全量扫描。

### Q28 如何认证与隔离

.env 中配置 token:user_id 表，后端解析 Bearer 令牌并映射身份，
所有用户数据接口检查请求 user_id 与令牌一致。无令牌或错误令牌 401，越权 403；
令牌未配置时拒绝启动。hmac.compare_digest 用于降低敏感比较的计时泄漏风险，
但不是宣称整个接口严格恒定时间或没有其他安全风险。

当前 Streamlit 仍使用服务端一把令牌，不具备各访客独立登录。
记忆先提候选，后端签发十分钟有效的一次性 review_id；
保存必须明确 confirmed=true、用户和候选字段完全一致，并再次执行规则。
服务端无法证明真人点击，只能验证确认请求与已审核候选绑定。

### Q29 如何测试而不调用真模型

纯函数测试、假模型节点测试、内存 SQLite 服务测试和 FastAPI 依赖覆盖测试。
认证另用真实比较函数，HTTP 用 TestClient 或 MockTransport，不消耗模型 Token。
单测验证覆盖到的代码逻辑；真实模型质量必须单独评估。
测试数量会变化，引用最新测试输出，不在文档里固化“所有版本都 113 项”。

## 7 局限与改进

### Q30 数据扩大后怎么办

基于测量选择 ANN 检索、倒排索引、元数据过滤、批量建索引与更新策略。
十万条 512 维 float32 裸向量约 195 MiB，但实际内存还包含归一化副本、索引、文本等。
延迟取决于设备与并发，不预设固定毫秒数；校验逻辑也需要随证据大小评估成本。

### Q31 如果重新做如何改进

先冻结一组有来源依据的评估样本，再实现最小链路；
尽早统一服务入口、审核协议和配置；保存运行记录再作效果对比。
后续拆出真正未参与调参的测试集，并增加失败案例，而不是只扩充正例。

### Q32 当前不足

两部法律覆盖有限；尚无 Rerank；引用检查不保证结论蕴含；
样本少且独立测试划分不足；网页共享服务端令牌；无完善限流与云部署。
审核缓存是单进程内存态，重启后需重新提取，多 worker 前需共享存储。
删除涉及两个数据库，没有跨库事务；不要与同一会话正在进行的回答同时操作。
没有公开长期记忆删除接口，也没有承诺完整隐私识别。

### Q33 如何说明 AI 辅助

可以如实说开发和排错使用了 AI 辅助，说明自己理解、复现和验证过的部分。
不必声称能解释每一行，也不要把未独立完成的功能说成独立设计。
用具体代码和测试展示已掌握的能力，并坦诚仍需补习的地方。

### Q34 这个算 Agent 吗

它是受约束的轻量工具调用 Agent：第一轮强制查资料，之后模型可继续调用工具或结束，
程序执行工具、回传结果、保存状态并校验最终输出。
不能说第一轮由模型自主决定“要不要查”，也不要将所有固定 RAG 流程都称为 Agent。

### Q35 为什么用 DeepSeek

当前选择已有 API 配置和中文应用场景。base_url 可配置，但仍依赖 Responses、
函数调用和结构化输出协议，其他“OpenAI 兼容”服务未必支持全部能力。
没有模型对比实验时，不宣称它一定比其他模型更便宜或更准确。

## 8 面试反问

可以询问岗位前三个月希望解决的问题、团队如何评估 Agent 质量，以及检索或工具链的主要难点。
根据交流自然选择，不预设面试官会采用某一技术栈。

## 9 当前事实速记

- 语料 205 条，其中劳动法 107 条、劳动合同法 98 条。
- BAAI/bge-small-zh-v1.5，512 维；文档建索引 batch_size=16。
- 向量与 BM25 等权融合；向量阈值 0.6，关键词覆盖率阈值 0.15，默认 Top-K=4。
- 模型最多调用五轮；图递归上限二十步。
- SSE 推处理阶段，答案校验后再展示，不是逐 Token。
- 用户身份由令牌确定，当前网页访客仍共用一个服务端账号。
- 删除同时清理该用户该会话的检查点与聊天历史，保留长期记忆。
- 保存记忆必须带一次性 review_id 和明确确认，重启后重新提取。
- 报告中的通过率必须同时说明样本量、版本、时间和是否真实重跑。
