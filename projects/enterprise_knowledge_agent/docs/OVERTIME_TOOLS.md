# 日历与加班费工具（官方联网＋缓存版）

新增的两个函数已注册到 ToolRegistry，模型可以通过 Function Calling 调用，而不是只能在页面点击按钮计算。原来的混合检索工具保留。

## 分工

1. 模型从用户消息提取日期、工资、工时和确认条件；不允许自行补年份或假设条件。
2. `query_holiday_calendar` 从已审核的官方来源获取年度日历，或复用24小时内缓存，返回逐日类型。
3. `calculate_overtime_pay` 独立再次查询日历，选择程序内固定倍率，使用 Decimal 计算。
4. LangGraph 把工具结果交回模型；最终校验节点用服务器生成的金额与明细替换模型的计算性回答，防止模型改数。
5. 法律、政策、日历资料继续进入本轮引用白名单。算式和工具输出不冒充法律原文。

如果计算工具返回缺参或不支持，后端最终只返回说明或追问，不展示模型自行编造的金额。一个回合存在多个计算请求也拒绝混用结果。

## 支持边界

- 当前接入中国大陆2025、2026年的官方来源；未知年份明确提示尚未接入，不等于官方未发布。新增年份需要审核来源、适配解析与补测试，不做任意网页搜索后直接算钱。
- 仅用户确认实行标准工时、实际工作休息安排遵循该日历的情形。
- 仅节假日与休息日，每天工作小时数相同，且不超过 8 小时；单次区间最多 31 天。
- 日工资必须由用户确认是适用的加班工资计算基数；基本工资不当然等于计算基数。实际适用口径要结合地区与工资规定核实。
- 休息日是否等时补休必须明确，各天不同请拆开计算。法定节假日不能用补休代替相应加班工资。
- 不计算普通工作日延时加班、特殊工时制度、个性化排班、超过八小时的分段、已经支付金额的扣减或应补发差额。
- 金额逐日四舍五入到分后汇总。结果不含正常工资，不是个案法律认定或争议裁决。
- 条件是否确实由用户确认，目前仍依赖模型遵守提取指令；工具校验类型与显式确认字段，不声称验证了真实劳动事实。缺参追问和错算拦截有本地测试，但真实模型提取效果需另行评估。

## 例子

原问题：“我在10月一号到10月5号加了5天班，基础工资每天300元，加班工资多少？”

不能立即给出确定金额，应补问年份、每天工时、工资基数口径、工时制度及实际排班、休息日补休情况。

若确认：2026-10-01 至 2026-10-05、标准工时并遵循全国日历、每天8小时、300元为适用日计算基数、休息日未补休，则：

| 日期 | 类型 | 倍率 | 加班费 |
|---|---|---:|---:|
| 10月1—3日 | 法定节假日 | 3 | 300 × 3 × 3 = 2700元 |
| 10月4—5日 | 休息日 | 2 | 300 × 2 × 2 = 1200元 |
| 合计 | 按上述前提的最低标准 | | 3900元 |

若两天休息日均已安排等时补休，对应两天工具按0元额外加班费计算，法定节假日部分仍为2700元。不能把五天全部按三倍计算。

### 数据路径与缓存策略

```text
有明确年份与日期 → 检查该年官方来源是否已接入
                     ↓
         24小时内且重新解析校验通过的缓存？
             ├─ 是：使用缓存，标记cache
             └─ 否/强制刷新：联网获取 → 校验 → 原子写缓存，标记network
```

- 缓存路径：`data/holiday_calendar/年份.json`，不提交Git。存公开来源、提取载体和获取时间，不存用户问题、工资或凭证。
- 每次读缓存重新解析来源内容，验证年份、标题、假期栏目、法定日数、范围/补班冲突和时间有效性。
- 默认24小时TTL，按UTC保存带时区时间；结果和计算明细显示获取时间、有效期、network/cache与stale=false。
- `refresh_calendar=true`明确要求刷新，即使有新鲜缓存也联网；刷新失败不退回旧缓存。
- 缓存过期、损坏、站点连接失败、解析失败时，返回`calendar_unavailable`，不产出金额，不回退到旧内置表。
- 下载仅允许固定官方域名及HTTPS，检查重定向、状态码、内容类型、大小和超时；网页不作为模型指令。
- PDF来源使用pypdf抽取文字，限制下载大小和页数，不执行JavaScript、OCR或猜测缺失内容。
- 出站请求可以遵循环境代理，另支持`HOLIDAY_HTTP_PROXY`显式指定代理；本地前后端HTTP客户端仍不使用出站代理。
- 单进程锁与原子替换避免半写文件；未实现跨进程下载去重、后台定时刷新或全天候可用性承诺。缓存未过期也不保证网站未刚刚更正，必要时手动刷新。

## 测试与运行

新增轻量PDF文字解析依赖`pypdf==6.21.4`；没有重建向量索引的要求。修改发生在独立发布副本 `D:\量化agent\labor-law-knowledge-agent`，旧 `agent-learning` 目录未同步修改。

在仓库根目录，使用安装好依赖的 Python 运行：

```cmd
python -m pip install -r requirements-dev.txt
python -m pytest -q projects\enterprise_knowledge_agent\tests
python -m projects.enterprise_knowledge_agent.scripts.refresh_calendar --year 2025 --refresh
python -m projects.enterprise_knowledge_agent.scripts.refresh_calendar --year 2025
python -m projects.enterprise_knowledge_agent.scripts.run_backend
```

前一个日历命令强制联网，后一个应在有效期内返回cache；两个命令均不调用模型、不需要API Key。可以将年份换成2026验证自己网络，失败时先排查官方来源连通性。

前端在另一个终端启动，端口建议8502。需要配置本副本的 `.env` 并具有可用的 DeepSeek 模型权限。真实问答会调用收费API；自动化测试只使用替身模型。
